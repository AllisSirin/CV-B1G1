# コンビニ 1+1 まとめ

セブン‐イレブン・ファミリーマート・ローソンの「1個買うと1個もらえる」を一つの画面でまとめて見る。
店舗アイコンを押すとその店だけ、`すべて` を押すと四つの出典をまとめて表示する。

[English README](README.md)

## 動かす

```
cd konbini && node server.mjs   # http://localhost:5176
bun test                        # 81 tests
```

## 出典

| アイコン | 出典 | ページ |
| --- | --- | --- |
| 7 | セブン‐イレブン プライチ | `https://www.sej.co.jp/cmp/plaichi.html` |
| F | ファミリーマート レシートクーポン | `.../2023_1buy1-receipt_cp.html` |
| F | ファミリーマート ファミペイ限定 | `.../famipay_1buy1_cp.html` |
| L | ローソン 1個買うと1個もらえる | 商品・おトク一覧から毎週の記事を探して入る |

ローソンは週ごとに記事の URL が変わるので、アドレスは書き留めず三重に探す。

1. `/recommend/index.html` で見出しが「1個/1本/1袋 買うと…もらえる」のリンクを **すべて** 集める（同じ週に二つあることがある）。
2. 見出しの言い方が変わって見つからなければ、`/lab/tsuushin/` の最新記事四本を直接開き、本文に 1+1 の項目があるかで判定する。
3. どちらも失敗したら、キャッシュの前回データを「読み込み失敗…（前回のデータを表示）」と一緒に返す — 画面が空にならない。

`2個買うと1個もらえる` のように条件が違う記事は拾わないよう、先頭の数字は 1 に固定してある。

## 価格の表示

`lib/catalog.mjs` が店ごとの商品一覧ページ（セブン `/products/a/*`、ファミマ `/goods/*.html`、ローソン `/recommend/original/*`）を
12 時間キャッシュで取得し、`名前 → 税込価格` の索引を作る。価格を付けるのは **名前が完全に一致した商品だけ**（公式商品ページへのリンクも付ける）。
部分一致を許すと「大粒ラムネ」に「大粒ラムネ アイスボックス味」の値が付いて別の価格になるので、あえて禁じている。

一覧に無い商品は `lib/lookup.mjs` が **各店の自社検索** で探す。
セブンは商品データベース検索 **`/products/a/itemresult/?key=…&limit=100`** を使う — 結果が商品一覧と同じ形
（`div.list_inner` + `item_ttl` + `item_price`）なので、`lib/catalog.mjs` のパーサーで **名前と価格をその場で** 読める（商品ページを開かない）。
ファミマは検索画面が呼ぶ MarsFlag の JSON から商品ページを見つけ、`lib/itempage.mjs` が価格を読む。

セブンのモバイル全文検索（`search.html?kw=`）は **使わない** — 最近発売分しか入っていないため
「綾鷹」「カップヌードル」「リポビタン」のような定番商品が一件も出ず、しかも Shift_JIS なのでそのまま読むと名前が化ける。
商品データベース検索に切り替えたら、その定番商品が `綾鷹 ６５０ｍｌ 187円`、`ロッテ パイの実 256円` とすぐ取れた。

検索は語ごとの部分一致なので、商品名をそのまま入れると表記の違いで 0 件になりやすい
（公式の題名が「森永 ｉｎバーエネルギー サツマイモ」なので `森永inバー` は部分文字列ではない）。
そこで `lib/price.mjs` は **一番長い語ひとつ → 商品名そのまま → 長い語ふたつ** の順に三回まで尋ねる。
語ひとつで先に尋ねる方が、一枚の結果で同じ系列（カップヌードル 7 種）をまとめて解決できて要求が少ない — 同じ語は一回の更新の中で一度しか取得しない。
セブンの商品ページには地域別のアドレス（`/item/480112/chugoku/`）もあるので、アドレスではなく **商品番号** で重複を消す。

名前が完全に同じでなくても、一方が他方の先頭部分で残る尻尾が短ければ（6 文字以下）価格を読む。ただし画面には `≈` と
読み取った商品名を一緒に出す。尻尾に数字や `パック`・`箱`・`入`・`ミニ`・`どんぶり`・`ビッグ`・`大盛` のような
まとめ・規格の表示があるときは価格が変わるので認めない（「マルちゃん正麺 醤油味」に `５食パック 734円`、
「サッポロ一番 塩らーめん」に `…塩らーめんミニどんぶり 168円` が付く事故を防ぐ）。
見つけた価格はその deal が終わるまで `data/prices.json` に残り（見つからなかったものは 7 日）、一度の要求で数件ずつしか探さず相手のサーバーを労わる。

ここまでの数え方はすべて **店ごと**で、店をまたいで合算しない。セブンは短い時間にまとめて尋ねると **403** を返し
以降の要求も全部弾かれるので、403 や通信の失敗は **「価格なし」としてキャッシュせず**（すると 7 日間その商品を探さなくなる）、
**その店だけ 10 分休み**、ほかの店は探し続ける。一度の更新で探す件数も店ごとの割り当てなので、
分からない商品が多い店が次の店の分を食べてしまわない。画面は価格が揃うまで数秒ごとに更新を呼ぶので、休まないと叩き続けてしまう。

注意: 三社とも商品ページを出すのは **自社商品（PB）と一部の新商品** が中心。1+1 の対象はほとんどメーカー（NB）商品なので、
2026-09-18 時点で価格が付くのは 50 品のうち 14 品。ローソンは検索そのものが外部ウィジェットで自社商品しか載せないため、価格を得る先が無い。
価格が分からない商品には「メーカー 商品名 価格」を検索する `Googleで価格を調べる ↗` のリンクを付ける — 無い数字を作らない。
店の検索は自社サイトに載せた商品しか出さないので、メーカー商品には役立たなかった。

## 構成

- `lib/{seven,familymart,lawson}.mjs` — ページごとのパーサー。結果は `{ periods, deals:[{ periods, buy, get }] }` の一つの形に揃える。
- `lib/html.mjs` — 依存なしのタグ抽出（入れ子の深さを数えてブロックを丸ごと切り出す）。
- `lib/cache.mjs` — `data/cache.json` に 3 時間キャッシュ。取得に失敗したら古いデータをエラーと一緒に返す。
- `public/period.mjs` — 「9月24日（木）～10月7日（水）」のような期間を読んで `発券中 / 引換のみ / 開始前 / 終了` を決める。サーバーと画面で共用。
- `lib/catalog.mjs` — 商品一覧の索引と価格の突き合わせ。`lib/{lookup,itempage,price}.mjs` — 公式検索・商品ページの読み取り・価格台帳。
- 画面の文字はすべて日本語（`public/*`、`lib/sources.mjs`）。カードは `これを買うと` → ↓ → `これがもらえる` の縦の流れに品目数を添える。
- 期間はセブンと同じく **カードごと** にバッジで出す（企画全体の期間もその deal に掛かる期間なのでカードへ降ろす — まとめの見出しに期間は置かない）。値は公式の表記のまま置き、`tidyPeriods()`（`public/period.mjs`）は同じ性格（購入／引換）で同じ期間がラベルだけ変えて二度書かれている箇所（ローソン `対象期間` = `発券対象商品購入期間`）だけを一行に縮める — 残す方は何の期間か分かる長いラベル。
- 状態のバッジは **普通ではないときだけ** 出す。発券期間が過ぎた deal はサーバー側で既に外れているので、「購入でクーポン発券中」は全部のカードに同じように付いて何も教えてくれない — バッジを出すのは `開始前` と期間が読めなかったときだけ。発券／引換の期間バッジはそのまま残す。
- 企画（チップ）の行は一つの店に企画が二つ以上あるときだけ出す — ホームでは店タブと重なるだけだった。
- `public/favorites.mjs` — 気になる 1+1（★）。単位は **カード（deal）一つ**。deal の番号は週ごとに消えるので、中の商品名で deal を見分ける — `dealKey()` が買う側・もらう側の最初の商品名を `買う>もらう` で繋ぎ、`favKey()` が全角・半角・空白・記号を落として表記が少し違っても同じ deal と見る（組み合わせが変われば別の deal）。保存先は `localStorage["konbini.favorites.v2"]` — ログインが無いので静的版でもそのまま使えて、保存を止めたブラウザでも落ちない（そのセッションだけ覚える）。★ はカード見出しのバッジ列の右端、ツールバーの `★ 気になる件` は保存したカードだけを残す。
- **今から行ってもクーポンを受け取れない deal は出さない** — `loadSource()` が `withoutEnded()`（`public/period.mjs`）を通る。`終了` だけでなく **`発券`（購入）期間が過ぎた deal も外す** — 引換期間が残っていても（`引換のみ可能`）新しくクーポンは受け取れず、それは既にクーポンを持っている人の話（セブンのプライチが先週の商品を「※無料クーポンの発券は終了しています」と載せ続ける — 実測 21 件のうち 13 件がそうだった）。期間が読めなかったものは外す根拠が無いので残す。キャッシュのファイルは読んだままにして、絞り込みは出すときだけ行う。開始前（`開始前`）も残す — もうすぐ使える情報だから。
- ツールバーの `いま使えるものだけ`（`#active-chk`）は **絞り込む対象があるときだけ** 出す。`終了` はサーバー側で既に外れているので残るのは `開始前` だけ — 始まっていない企画が載る週にだけ現れる。
- `/img?u=` — 元サイトの画像をサーバーが代わりに取得する（許可したホストだけ）。取得した画像は `data/img/<sha1>.<ext>` に残し、以降は自分の側から返す（`lib/images.mjs`）— 見る人が増えてもコンビニのサーバーを叩かない。スナップショットもこのキャッシュを共有する。

## 共有（無料で出しっぱなしにする）

`node scripts/snapshot.mjs` が `dist/` を一つ作る — `public/` の写し + `data/deals.json`（その時点の deal と価格）+ `img/`（取得した商品画像）。
これならサーバー無しでどこにでも置けて、見る人がコンビニのサイトを叩かない。

- 画面はまず `/api/deals` を呼び、無ければ（静的版）`data/deals.json` を読む（`fetchDeals()`）。静的版では `更新` ボタンを隠す。
- 画像はスナップショットが `img/<ハッシュ>.jpg` に置き換えるのでプロキシは要らない。サーバーで動かすときはそのまま `/img?u=` を通る。
- 自動更新: `.github/workflows/pages.yml` が一日二回（06:20・18:20 JST）スナップショットを作って GitHub Pages に上げる。公開リポジトリなら無料。
- **`data/prices.json` は種としてリポジトリに入れている**（`data/` で唯一追跡するファイル — `.gitignore` 参照）。ランナーは空のキャッシュから始まるので、値を全部また探しに行ってセブンに **403** で止められ、そのあとに取る商品画像まで空になる。
- ビルドとビルドの間は `data/` 一式（値**と**取った画像）を `actions/cache` が運ぶ。キーは毎回変え（`konbini-data-<run_id>` + `restore-keys`）、直前の分を受け取る。だから各ビルドが尋ねるのは本当に新しい分だけ。リポジトリの種はそのキャッシュが消えたときの冷え切った出発点。
- スナップショットは今やっている deal が使う分だけ残す。終わった deal の値と画像は捨てる（`prune`・`pruneImages`）。同じ商品が後で別の deal に出てきたらもう一度取りに行くので、古い値や画像を使い回さず、キャッシュも際限なく膨らまない。取得に失敗した出所・今は deal が無い出所は触らない — 一度の失敗で種が空にならないように。
- 画像は値を探す**前**に取る。値を探していて 403 をもらっても、画像まで一緒に失わない。
- git 無しで今すぐ出すなら、`dist/` フォルダを Cloudflare Pages や Netlify Drop に放り込めばよい（更新は手動）。
- リンクプレビュー: `public/index.html` に og/twitter タグ、画像は `public/og.png`。`node scripts/ogimage.mjs` が og.png・icon-192・icon-512 をパッケージ無し（zlib だけ）で作り直す — フォントが無いので「1+1」は四角で描かれる。スナップショットは `SITE_URL` があれば og:image・og:url を絶対アドレスに書き換える（ワークフローが Pages のアドレスを渡す）。
- ホーム画面への追加: `public/manifest.webmanifest` + `public/sw.js`。サービスワーカーは **https のときだけ** 登録する（開発中の localhost がキャッシュに閉じ込められないように）。画面のファイルを直したら `sw.js` の `VERSION` を上げる。
- 画面の下に非公式・出典の案内を置く（`public/index.html` の `footer.note`）— 各社とは無関係で、公式サイトの内容を自動で取得して並べたものであり、条件は公式ページで確認してほしいという案内。
